# 大屏操作与联动说明

> 对应脚本：`scripts/08_dashboard.py`
> 技术栈：Streamlit 1.66 + Plotly 7.1 + Pandas（全 Python，无 BI 软件）
> 数据源：`data/clean/` 三张清洗表 ＋ `outputs/tables/rfm.csv`，**不重算任何模型**

---

## 一、启动

```bash
# 1. 激活虚拟环境（Windows）
.venv\Scripts\activate.bat

# 2. 在仓库根目录启动（路径很重要，脚本用相对路径读数据）
streamlit run scripts/08_dashboard.py

# 3. 浏览器自动打开 http://localhost:8501
```

**版本要求**：Streamlit ≥ 1.49（用到 `plotly_chart` 的 `on_select` 点击回调与 `width="stretch"`）。
若报 `unexpected keyword argument 'width'`，说明版本过低，脚本内已有 `wide_plotly()` 兼容层会自动回退。

**端口被占用**：`streamlit run scripts/08_dashboard.py --server.port 8600`

## 三、六个组件与联动矩阵

| # | 组件 | 形式 | 受哪些筛选影响 |
|---|---|---|---|
| ① | 全局筛选器 | 侧边栏：时间滑块 / 品类多选 / 州下拉 | — |
| ② | KPI 卡 ×4 | GMV、订单数、客户数、客单价 | 时间 ✔ 品类 ✔ 州 ✔ |
| ③ | 月度 GMV 趋势 | 折线 + 面积填充 | 时间 ✔ 品类 ✔ 州 ✔ |
| ④ | 品类结构 Top10 | 环形图（含"其余品类合计"） | 时间 ✔ 品类 ✔ 州 ✔ |
| ⑤ | 各州销售分布 | 散点地图（点大小 = GMV，可点击） | 时间 ✔ 品类 ✔ 州 ✔ |
| ⑥ | RFM 客户分群 | 散点（R×F，色 = 8 分群） | 时间 ✔ 品类 ✔ 州 ✔（只筛客户，不重算） |
| ⑦ | 品类销售明细 | 表格 + Top N 滑块 + CSV 下载 | 时间 ✔ 品类 ✔ 州 ✔ |

**下拉联动（下钻）**

在右侧地图上**点击某个州的圆点**，脚本会把「③ 州」筛选器自动切到该州并重跑，KPI、趋势、结构、明细表、RFM 全部收窄。若浏览器端选中事件不生效（极少数环境），直接用侧边栏的州下拉框，效果完全等价。

> 实现细节：点击后写入 `pending_state` 并在下一轮启动时消费，同时用 `last_map_click` 防止重复触发死循环。

## 四、口径（答辩必问）

| 指标 | 口径 | 数值（全量筛选） |
|---|---|---|
| 大屏 GMV | `items_clean.price` 汇总，**商品金额、不含运费** | R$ 13,330,627 |
| 订单数 / 客户数 | `orders_clean` 去重计数 | 97,308 / 94,136 |
| 客单价 | 上述 GMV ÷ 订单数 | R$ 136.99 |
| RFM 的 M | `payment_total` 汇总，**含运费** | R$ 15,551,540 |

**为什么大屏用商品金额而不是支付金额**：品类筛选必须落到订单项粒度（`items`），若用订单级 `payment_total`，筛选品类时无法拆分一张订单里不同品类的金额，只能整单计入，会让"品类 GMV"虚高。为保证六个组件同一套口径，统一用 `price`。

**代价**：大屏 GMV（13.33M）与 RFM/预测图的 15.55M 不同。这**不是错误**，是两个口径。论文中已分别标注，答辩时按上表回答即可。

## 五、三分钟演示流程（建议顺序）

1. **开场**：默认全量，读 KPI——1333 万 GMV、9.7 万单、9.4 万客户，客单价 137 雷亚尔。
2. **时间下钻**：把时间滑块收到 `2017-01 ~ 2017-06`，KPI 立刻降到 198 万 / 1.4 万单——展示"平台在成长期"。
3. **品类下钻**：选 `health_beauty` + `watches_gifts`，GMV 降到 29 万，但**客单价升到 191**——引出"高客单品类"话题。
4. **地图下钻**：点圣保罗州（SP）圆点，或下拉选 SP，GMV 收窄到 9.9 万——说明销售高度集中在东南部。
5. **RFM**：滚到右下散点图，指出 97% 的点贴在 F=1 这条线上——直接呼应"一次性交易平台"的核心结论。
6. **收尾**：明细表拉 Top 20，点下载导出 CSV，说明结果可交付、可复核。

## 六、已知限制（主动说明，别等被问）

| # | 限制 | 原因 | 应对 |
|---|---|---|---|
| 1 | RFM 图不随筛选重算 R/F/M | 重算会与 `03_rfm.py` 的口径分叉，且违反"不重算模型" | 只按当前客户集合过滤展示，图底部已注明 |
| 2 | 地图点击需浏览器端选中事件 | Streamlit 版本差异 | 侧边栏州下拉等价可用 |
| 3 | 州坐标用客户经纬度均值 | 州级 geojson 需外部文件，本项目不引入来源不明的数据 | 散点质心足够表达分布，不影响排名 |
| 4 | 品类筛选后 GMV 下降明显 | 只统计所选品类的金额，属预期 | 口径已在页面底部与本文说明 |
| 5 | 首屏加载约 2–4 秒 | 首次读三张大 CSV | 已用 `@st.cache_data`，之后交互不再重读 |

## 七、常见问题

**Q1：页面空白/一直转圈？**
看终端有没有报错。最常见是工作目录不对——必须在仓库根目录启动，脚本用 `data/clean/...` 相对路径。

**Q2：中文显示成方块？**
Streamlit 页面本身是浏览器渲染，不存在字体问题；若图表内文字乱码，检查浏览器缩放或用 Chrome/Edge。

**Q3：改了 CSV 但图表没变？**
`@st.cache_data` 有缓存。按 `C` 清缓存，或在菜单里点 "Clear cache"。

**Q4：能部署到公网吗？**
可以（Streamlit Community Cloud），但 Olist 数据是 CC BY-NC-SA 4.0，**非商业**用途没问题，公开时须保留署名与同协议声明。

## 八、答辩一句话总结

> 这个大屏不是把静态图搬上网页，而是把 5 个模型的结果串成一条可下钻的证据链：
> 从大盘（KPI）→ 时间（趋势）→ 结构（品类）→ 空间（州）→ 客户（RFM）→ 明细（可下载），
> 每一层筛选都实时重算同一套口径，评委可以现场指定任意组合验证结论是否成立。
